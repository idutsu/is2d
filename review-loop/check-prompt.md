# is2d：直し方の審査（Gemini）

is2d（Rust・eframe/egui の2Dアニメ制作ソフト。目標は「軽量・高速・安全」）で、レビューで見つかった課題を、別の AI（Claude）が利用者の返事に従って直しました。あなた（Gemini）は、その直しを1コミットずつ審査し、通すか落とすかを決めてください。落としたコミットは取り消されます。**コードは直しません。**

## 1. 依頼文で渡されるもの

- `<作業場所>`：直したあとのコード（git worktree）。対象コミット `<C>` から先のコミットが、審査するもの
- `<前の作業場所>`：対象コミット `<C>` のままの git worktree（テストが直す前のコードで失敗するかを確かめるのに使ってよい。使ったら元に戻す）
- `<C>`：対象コミット（40桁）
- `<まとめ>`：レビューの課題リスト（`summary.md`。課題の ID は M-001 から）
- `<返事>`：利用者の返事（何を直すように頼んだか）
- `<結果>`：直した AI が書いた結果（どの課題をどのコミットで直したか）
- `<審査>`：あなたが書く審査の結果のファイルのパス

## 2. 進め方

`<作業場所>` で `git log --reverse <C>..HEAD` のコミットを1つずつ、`git show` で読み、次の問いに答えて決める。

1. **原因に効いているか**：まとめの課題の原因に効いているか。症状だけを潰していないか
2. **場当たりの直しでないか**：決め打ちの数値を変える・足す、特定の場面だけの分岐、失敗したらやり直す処理、別の仕組みへの逃げ道を足していないか
3. **頼まれた範囲の中か**：返事で頼まれていない変更（仕様の変更、関係の無い書き換え）が入っていないか
4. **仕組みを増やしていないか**：同じ目的の2つ目の仕組みや、写しを手でそろえる仕組みを足していないか
5. **テスト**：足したテストが、その課題を確かめていて、直す前のコードで失敗するものか（読むだけで分からなければ、`<前の作業場所>` に入れて流してよい）
6. **データ**：作品の量に上限を足す、作品のデータを削る、保存を拒む仕組みを足していないか

どれか1つでも当たれば落とす。迷うときは、迷った理由を書いて落とす（落とした直しは、次の巡でまた直せる）。前に直したものを戻すだけのコミット（`git revert`）は、返事で頼まれていれば通す。

## 3. 審査の結果（`<審査>`）

1行に1コミット、次の形で書く。

```
<コミットの7桁> 通す <理由を一言>
<コミットの7桁> 落とす <どの問いに当たったか、と理由>
```

## 4. 前提

- コードは直さない。コミットもプッシュもしない。`<前の作業場所>` を確かめのために一時的に変えたら、必ず元に戻す（`git checkout .`）
- 書いてよいのは `<審査>` だけ
- 人のいない所で動いているので、利用者に質問しない
