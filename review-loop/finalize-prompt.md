# is2d：審査で落とされた直しを戻し、利用者への報告を書く（Claude）

is2d の課題を、利用者の返事に従って直し（`<結果>`）、別の AI（Gemini）が1コミットずつ審査しました（`<審査>`）。あなた（Claude）は、落とされた直しを戻して、利用者への報告を書いてください。**新しい直しはしません。**

## 1. 依頼文で渡されるもの

- `<作業場所>`：直したあとのコード（リポジトリのフォルダ）。対象コミット `<C>` から先が、今回の直し
- `<C>`：対象コミット（40桁）
- `<まとめ>`・`<返事>`・`<結果>`・`<審査>`：課題リスト、利用者の返事、直した AI の結果、審査の結果
- `<報告>`：あなたが書く、利用者への報告のファイルのパス

## 2. 進め方

1. `<審査>` で「落とす」とされたコミットと、`<審査>` に書かれていないコミットを、新しいものから順に `git revert --no-edit` で戻す。コミットメッセージの最後に、戻した理由（審査の理由）を1行足す（`git commit --amend`）
   - 戻すときにぶつかる（後のコミットが、戻すコミットに頼っている）ときは、その後のコミットも戻す。戻した理由に、そのことを書く
2. `cargo fmt --check`、`cargo test --release`（全部）、`cargo clippy --release --all-targets -- -D warnings` を流す。通らなければ、原因になったコミットを同じように戻す（新しい直しで通そうとしない）
3. `<作業場所>` の `git status` が空であることを確かめる
4. 利用者への報告を `<報告>` に書く

## 3. 報告の書き方

やさしい日本語で、結論から、短く。1つの項目に1つのことだけを書き、見出しと箇条書きで拾い読みできるようにする。

1. **結論**（3 行以内）：直した数・審査で落とした数・やめた数。このあと自動でプッシュし、新しいコミットをまたレビューすること
2. **直したもの**：課題の ID（M-xxx）、コミットの7桁、利用者から見て何が変わるかを一言
3. **審査で落としたもの**：ID と、審査の理由（次の巡でまた直せること）
4. **直さなかったもの**：やめた理由（設計が要る・原因に効く直し方が見つからない・確かめたら問題が無かった）、返事が分からなかった所
5. **Mac で確かめてほしいこと**：テストでは確かめられないもの（見た目・手触り・速さの体感）があれば、何をどう操作して何を見ればよいか
6. **戻したいとき**：次の返事に「M-xxx の直しを戻して」と書けば戻せること
7. 全テストの数と clippy の警告数

## 4. 前提

- 新しい直しはしない。書き換えてよいのは、戻すコミットを作ることと、`<報告>` を書くことだけ
- プッシュしない（このあとスクリプトが、整形・テスト・clippy をもう一度確かめてからプッシュする）
- 人のいない所で動いているので、利用者に質問しない
